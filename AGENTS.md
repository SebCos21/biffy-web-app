## Architecture rules
- The app is Flutter/Dart (root `lib/`); the previous React/Lovable web app lives in `legacy_web/` only as a behavior/design reference — do not add features there.
- The whole app uses **Clean Architecture + Bloc** (HU-2 finished the migration). Every module is a vertical slice like orders: `lib/domain/` (entities, repository interfaces, ports, use cases, typed results with Spanish messages in `*_errors.dart` — pure Dart, no Flutter/Supabase) ← `lib/data/repositories/` (in-memory + Supabase implementations of the domain interface) and a Bloc/Cubit in `lib/features/**` (events → use cases → immutable state with `copyWith`, no Equatable). Dependencies only point inward; `test/architecture_test.dart` enforces it, including that every Bloc/Cubit imports only the domain (no `data/`, `shared/`, `app/`, Supabase or GetIt).
- There are no `ChangeNotifier`/`ValueNotifier` classes, no `package:provider`, no `SessionController` and no `ControllerScope` in `lib/`; do not add them back. Each repository has two implementations: in-memory (demo, used by the tests) and Supabase (real backend, enabled only when `AppConfig.hasSupabase`); do not add a third source of truth. Documented exceptions: `SessionRepository` is in-memory in both modes (device state) and `RewardsRepository`/`MerchantBoxesRepository` (HU-4) exist only with Supabase. Ports that a slice needs from another live in `lib/domain/ports/` and their adapters in `lib/shared/adapters/`.
- Session and auth: `AuthBloc` (global `LazySingleton`, `lib/features/auth/bloc/`) handles login, sign-up with role, restore, sign-out, active role, profile, business link, delivery point, default payment and settings through `AuthUseCases` (`lib/domain/usecases/auth/`) → `AuthRepository` + `SessionRepository`. `LoginCubit`, `RegisterCubit` and `UniversityVerificationCubit` sit on top of it. Sign-out calls the server; if the network fails it still signs out locally, returns `network` and the screen goes to `/login`. Events are processed asynchronously: when a screen navigates or reads the session right after (login, role or point change), it must `await bloc.request(event)` before `context.go`. The router uses `buildRouter(AuthBloc, refresh:)` with `StreamRefreshListenable` (`lib/app/auth_refresh.dart`, a hand-written `Listenable` over `AuthBloc.stream` that cancels its subscription on `dispose`). Cart: `CartCubit` (shared `LazySingleton`) plus `CheckoutCubit`, which only validates and delegates the order to `OrdersBloc` (`OrderPlaced`). Other slices: `CatalogBloc`, `NotificationsBloc`, `CourierCubit`, `WalletCubit`, `PreferencesCubit`, `AddressesCubit`, `UniversityCubit`. Screens read state from Blocs and never import `data/` implementations.
- Payments are a Bloc slice: `PaymentBloc` (`lib/features/buyer/payment/bloc/`) → `StartPayment`/`CheckPaymentStatus`/`RetryPayment` → `PaymentRepository` (domain), with `SupabasePaymentRepository` (Wompi Edge Functions + Realtime) and `InMemoryPaymentRepository` (demo) registered in GetIt. Wompi keys and secrets live **only** in Supabase Edge Functions; the app only receives the checkout URL. Online orders are created with `payment_status='pending'` and the restaurant sees them only when `approved`; cash is `approved` with `cash_tendered`/`cash_change`. A rejection returns to the cart with the reason and allows retry; expiry cancels and refunds Gotas/coupon. `payments`/`payment_events` are audited and RLS-protected, and `wompi-webhook` verifies the checksum and is idempotent.
- HU-4 sigue el mismo patrón: Cubits (`flutter_bloc`) en `lib/features/**` → casos de uso en `lib/domain/usecases/` → interfaces en `lib/domain/repositories/` y puertos en `lib/domain/ports/`; las implementaciones viven en `lib/data/repositories/` y los adaptadores en `lib/shared/adapters/`, inyectados por GetIt. Cubits: `RateOrderCubit`, `RewardsCubit`, `MerchantBoxesCubit`, `NotificationsCubit`, `EarningsCubit`. Los widgets nunca llaman a Supabase directo. Con Supabase los avisos de pedido los crea la base (0022), así que el notificador de pedidos remoto no crea avisos locales.
- **Inyección de dependencias con GetIt (obligatoria):** todo se registra en `lib/app/di/injection.dart`, por módulos (`lib/app/di/modules/`: `core`, `data`, `domain`, `presentation`). Repositorios y puertos son `LazySingleton` tipados por su interfaz; los casos de uso son `Factory`; los Blocs globales (`AuthBloc`, `OrdersBloc`, `CatalogBloc`, `NotificationsBloc`, `CartCubit`, `CourierCubit`, `WalletCubit`, `PreferencesCubit`, `AddressesCubit`, `UniversityCubit`) son `LazySingleton` con `dispose`; los cubits de pantalla son `Factory` (con `param1` si necesitan datos de la pantalla). Las pantallas piden lo que necesitan con `getIt<T>()` y leen los Blocs con `context.watch<T>()`/`BlocSelector` (publicados con `BlocProvider` en `app.dart`). Solo `lib/app/di/` importa implementaciones concretas, y la única decisión Supabase/memoria (`AppConfig.hasSupabase`) está en `data_module.dart`. Las pruebas usan `makeServices()` (`getIt.reset()` + dobles de prueba), nunca un constructor solo para tests; cada Bloc/Cubit necesita `blocTest` de éxito y de error. `test/architecture_test.dart` lo hace cumplir.
- Visibility of restaurants/dishes must go through `isReachable` (radius + couriers nearby + campus-only) in `lib/domain/catalog_rules.dart`, exposed via `CatalogBloc.reachableRestaurants/reachableDishes` — single source for the distance rule.
- Business rules (pricing, filters, order transitions, scheduling, recommendations) are pure functions in `lib/domain/` with unit tests; widgets never duplicate them.
- Orders are shared by buyer, restaurant and courier through `OrdersBloc` → use cases (`lib/domain/usecases/orders/`) → `OrderRepository`. Screens dispatch events (`bloc.add(...)` or `await bloc.request(...)` when they need the result) and read via `context.watch<OrdersBloc>()`; they never touch repositories or mutate `Order`. Allowed transitions live in `kAllowedTransitions`; with Supabase the server (RPC) decides and every `result` code is translated by `lib/domain/order_errors.dart`.
- Merchant products are saved into the shared catalog repository with the `CatalogBloc` event `DishSaved` (→ `CatalogUseCases` → `CatalogRepository`), so buyer screens and the radius rule see them without a second source.
- Mobile-first touch UI: shared pieces in `lib/core/widgets/`; yellow `#FCBD1A` primary, Sora/Manrope fonts bundled in `assets/fonts/`; every visible control must have a real action.
- Comment every class, function and widget with one short line saying what it is or does (Spanish, `///` for public members). New code without that comment is not done.
- Demo accounts (password `biffy123`) and the "Horario de demostración" setting keep the full three-role flow testable offline at any hour; `test/integration/full_flow.dart` drives that flow through the UI.
